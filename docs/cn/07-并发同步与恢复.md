# 并发、同步与恢复

每个 mutation 先 fetch/verify current main，再使用 expected-head CAS。Remote
mutation 使用 `--force-with-lease`，需要多个 ref 时使用 atomic push。

```text
chassiss sync --json
chassiss sync --all-work --json
chassiss sync --prune --json
```

`sync` 验证 remote main 是本地 verified head 的后代，拒绝 rollback、Project/
Root identity change 与分叉。验证成功后才推进 minimum checkpoint。`--all-work`
额外检查 current submitted/approved Work Refs；`--prune` 只清理已进入 main 的
临时 Transition refs，不删除 active Work 或 Archive Ref。

Pending Operation 状态：

```text
prepared → signed → published/reconciled
                    ↘ push-unknown
```

`push-unknown` 表示不能安全判断 remote 是否已接收；此时不能替换 Evidence 或
复用同一 Operation ID 生成另一语义操作。先执行 `sync`，让 CLI 检查 candidate
是否已在 verified main。

Archive Ref 对 submitted Attempt 的 cancel/supersede 是不可变保留点。创建
Archive Ref 与推进 main 必须原子完成；缺失、改写或 unreachable 会使历史验证
失败。

当前实现最多执行三次 semantic recompute/re-sign；Authority Transition 的本地
loopback remote 竞争已通过，全部 Action 和连续三次竞争的故障注入矩阵仍是
lock-candidate 差距；见
[实现差异登记](../12-implementation-differences.md)。
