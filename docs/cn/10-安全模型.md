# 安全模型

## 信任根

Trusted clone 的信任材料是 Project ID、Genesis Root fingerprint 和 minimum
checkpoint。三者必须通过 remote 之外的可信渠道获得。验证失败不更新 checkpoint。

已有项目 bootstrap 还要由 Master 固定 full source commit OID。旧 commit/tree
和 `docs/chassiss/onboarding/source-history.md` 只是 Root 签名的来源声明，不是
旧 history 的 Authority 背书；source `.git`、refs、credential 和 local State
不得导入。

## 密码学

- Git Transition 与 Work Commit：Ed25519 SSH commit signature；
- Grant Request：Ed25519 SSHSIG，固定 namespace；
- protocol digest：SHA-256 + object-type domain separation；
- State：RFC 8785-compatible canonical JSON + 单个 trailing LF；
- Operation/Evidence：canonical JSON，经 base64url trailer 绑定 commit message。

## 数据边界

不得进入 Git、JSON response、Error 或日志：

```text
private key bytes
secret-store unlock data
remote password/token
machine-local key path or worktree path inside shared Evidence
session/cache content
```

Local State 目录 owner-only，文件使用临时文件、fsync、atomic rename。POSIX
权限位会验证；Windows 当前依赖用户 profile 继承 ACL，独立 DACL 构造/验证是
lock 前差距。Candidate worktree 与 index 隔离。所有 Git/Check 调用使用 argv，
不用 shell 拼接。

## 不提供的安全性

CHASSISS 不 sandbox Task 代码或 Check 命令；恶意代码仍可能读取当前用户可访问的
secret。应使用独立 OS 用户、容器或受控 runner 做高风险构建。Same-actor Review
warning 也不等于组织独立性。

已知 file-key backend、真实 remote fault injection 等差距见
[实现差异登记](../12-implementation-differences.md)。
