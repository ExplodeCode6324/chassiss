# 旧项目迁移与差异

旧项目 v0.x 与当前 v1 是不同协议，不支持 dual-write、silent upgrade 或把旧
commit 自动解释为 Transition。关键变化：

- `.chassis/` 控制目录改为签名 Git Transition + 最小 `.chassiss/state.json`；
- 固定 role credential 改为 Key/Grant/Capability/Scope/Limit；
- `bootstrap` 改为 verified `context`；
- Requirements/Architecture/Mission/Tasks 改为 Architecture + 单轮 Taskbook；
- Git 从本地 backend 提升为共享账本和验证对象模型；
- Agent 不再直接操作 Git mutation。

建议迁移流程：

1. 冻结旧项目，固定 full source commit，并整理可选旧历史摘要；
2. Master 明确确认新 Project ID 与 Root trust anchor；
3. 在空目录运行 `bootstrap --source ... --ref <full-oid>`，导入 exact ordinary
   snapshot；
4. 确认 `docs/chassiss/onboarding/source-history.md` 只把旧 commit/tree 标成
   非权威参考；
5. 每个 Agent 生成 key 与 proof-of-possession Grant Request；
6. Root 发布 `architecture.establish` global Grant；
7. Architecture Agent 审计源码，生成、验证并建立首份 Architecture；
8. 根据新需求创建第一轮 Taskbook，重新定义 `writes`、`affects` 和 Checks；
9. 不把旧 credential、control event、`.git` 或 private/local State 放入新
   Git history。

完整操作步骤见[已有项目接入](13-已有项目接入.md)。

逐项架构对照、实现选择和未关闭差距见
[正式差异登记](../12-implementation-differences.md)。
