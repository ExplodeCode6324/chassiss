# 项目概述

CHASSISS 把多 Agent 开发拆成四层：

1. Git 保存签名历史、普通项目文件与共享合同；
2. Reducer 从 parent State、Semantic Operation、Execution Evidence 和已验证
   Git facts 计算完整 next State；
3. CLI 负责授权、Git mutation、worktree、Checks、签名、同步和恢复；
4. Agent 与人类负责需求、设计、实现和 Review 的语义判断。

一个 Git repository 对应一个 Project。`refs/heads/main` 是唯一权威主线。
Architecture 描述跨工作流的 Resource graph；Taskbook 描述当前一轮 Requirements、
Constraints、Tasks 与 Checks；Taskbook 归档后才能打开下一轮。

共享状态只有：

```text
.chassiss/state.json
docs/architecture.yaml
docs/taskbook.yaml
docs/taskbooks/archive/<taskbook-id>.yaml
signed Git history and retained refs
```

Private key、remote trust anchor、minimum checkpoint、pending Operation 和 managed
worktree registry 都在仓库外。Local State 不授予权限；每次授权只读取 current
verified State 中的 Grant。

CHASSISS 面向守规但可能犯错的 Agent。它限制工作流和审计边界，不是恶意代码
沙箱，也不证明实现本身符合需求。Review 仍需要真实语义判断。
