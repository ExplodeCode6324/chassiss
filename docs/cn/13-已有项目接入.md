# 已有项目接入

已有 Git 项目通过 Root-only source bootstrap 接入 CHASSISS。新 Project 的
权威 first-parent history 从 bootstrap commit 开始；旧 commit/tree 只作为
来源参考，不获得 CHASSISS Authority。

## 1. 准备 source

冻结旧仓库并选定 full commit OID：

```text
git rev-parse HEAD
```

接入前人工确认：

- source commit 是准备采用的 exact snapshot；
- 不包含 `.chassiss/**` 或 CHASSISS protected path collision；
- submodule 已 flatten、移除或另行处理；
- symlink 不逃逸仓库；
- secret、credential、`.env`、生成物和大文件不会误入新 Project；
- 可选 Markdown 历史摘要只记录仍有价值的版本、架构决策、迁移和已知债务，
  不包含本地路径或 secret。

上述 source 审查会改变选定 snapshot 时，必须先由 Master 明确新的 full commit
OID；CLI 不静默修改 source。

## 2. 创建 Root-only bootstrap

Root key 在 source 和目标目录之外生成。进入一个空目标目录：

```text
chassiss bootstrap \
  --project PRJ-EXAMPLE \
  --source /path/to/existing-repository \
  --ref <full-source-commit-oid> \
  --root-key KEY-ROOT-01 \
  --history /outside/project/history-notes.md \
  --json
```

`--history` 可省略。CLI：

1. 只读解析 exact source commit/tree；
2. 重新写入 ordinary blobs 和安全相对 symlink；
3. 拒绝 protected collision、submodule、非法 path 和逃逸 symlink；
4. 不复制 source `.git`、refs 或 credential；
5. 生成 protected
   `docs/chassiss/onboarding/source-history.md`；
6. 创建零 parent、Root 自签的 `project.bootstrap`。

随后运行：

```text
chassiss verify --full --json
chassiss context --json
```

此时 `architecture_blob=null`、`taskbook_blob=null`、`tasks={}`。Source history
document 和 State `project.source` 必须指向同一 source commit/tree/history
blob。

## 3. 授权 Architecture Agent

Agent 在项目外生成 key 和 proof-of-possession Request：

```text
chassiss key generate --id KEY-ARCHITECT-01 --actor architect --json
chassiss grant request \
  --project PRJ-EXAMPLE \
  --key KEY-ARCHITECT-01 \
  --capability architecture.establish \
  --task-scope '*' \
  --resource-scope '*' \
  --limits unbounded \
  --output /outside/project/architect-request.json \
  --json
```

Root 审核 Actor、Key、Capability 和全局 scope 后发布：

```text
chassiss grant add \
  --request /outside/project/architect-request.json \
  --grant-id GRT-ARCHITECT-01 \
  --root-key KEY-ROOT-01 \
  --capability architecture.establish \
  --task-scope '*' \
  --resource-scope '*' \
  --limits unbounded \
  --json
```

Architecture Agent attach/select 自己的 key；不要共享 Root private key。

## 4. 审计并建立 Architecture

先创建 project-bound 外部候选：

```text
chassiss architecture draft \
  --new \
  --output /outside/project/architecture.yaml \
  --json
```

Architecture Agent 对照 adopted ordinary snapshot 审计：

- Module 职责、路径边界和依赖方向；
- API 调用方、输入输出、错误与兼容边界；
- Schema 的持久化、消息和演进约束；
- Dependency 的用途、版本和运行约束；
- Config 的默认行为、消费者和安全边界；
- 构建、测试、部署入口与仍未知的风险。

扫描器或 Agent 可以生成骨架，但 CLI 结构校验不证明语义准确；Master 或独立
Reviewer 必须复核。

```text
chassiss architecture validate \
  --file /outside/project/architecture.yaml \
  --json
chassiss architecture establish \
  --file /outside/project/architecture.yaml \
  --reason "audited adopted source snapshot" \
  --key KEY-ARCHITECT-01 \
  --grant GRT-ARCHITECT-01 \
  --json
chassiss verify --full --json
```

Architecture establish 后，source anchor/history document 保持不变；Architecture
不能再回到 null。

## 5. 进入正常需求开发

根据正式 Architecture 讨论新需求：

```text
chassiss taskbook draft \
  --new \
  --output /outside/project/taskbook.yaml \
  --json
chassiss taskbook validate \
  --file /outside/project/taskbook.yaml \
  --json
chassiss taskbook open \
  --file /outside/project/taskbook.yaml \
  --reason "open first post-adoption workflow" \
  --json
```

Root 为 Builder、Reviewer 和 Integrator 分别签发最小 Grant，之后进入标准
Task start→Work→Check→Submit→Review→Integration→Taskbook archive 循环。

旧历史摘要只用于理解上下文。任何未来 Authority、Task 状态或验收结论都必须
来自 bootstrap 之后的 verified State 和 signed Transition history。
